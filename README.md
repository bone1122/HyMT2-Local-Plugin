# Hy-MT2 本地翻译 Bob 插件 v0.2.4

本插件通过 Bob 的 `$http` 调用本机懒启动管理器，使用本地 MLX Hy-MT2 模型进行翻译。默认 API 地址为 `http://127.0.0.1:8899/v1/chat/completions`。

## v0.2.4 更新

- 「自定义用户提示词（可选）」改为「提示词」。留空使用默认翻译指令，填写后替代默认指令，原文自动附加在提示词后。
- 「翻译风格」默认留空；留空时不添加风格要求，填写后才将风格要求加入提示词。
- 不再读取 `query.style` 或 `query.tone`。
- 新增「流式输出」开关，默认开启；Bob 1.8.0+ 且本地后端支持 SSE 时逐步输出，未获得可用流式正文时自动回退一次非流式请求。
- 修正了之前即使风格留空也会追加风格要求的问题。

## 提示词与翻译风格

插件设置提供两个独立选项：

- **提示词**：留空时使用默认翻译指令。填写后以自定义提示词替代默认指令，只支持 `{target_lang}` 占位符；待翻译原文会自动附加在提示词后。
- **翻译风格**：默认留空。留空时不添加额外风格要求，按默认翻译指令执行；填写后会附加「翻译风格要求：你填写的内容」。例如「学术论文严谨风格」「日常口语化风格」「科普语气」「商业正式语气」「新闻报道风格」「宣传文案风格」「小说风格」「法律合同风格」「中国古代文言文」。

提示词示例：

```text
请将以下文本翻译为 {target_lang}。
你必须在译文中保留等量的分隔符，绝对不可遗漏、转义或翻译该符号，并注意分隔符的位置。
理解原文核心意思后，用目标语言重新组织表达，而非逐字直译。
多用短句，主动拆分长句为短句，减少从句嵌套，提高可读性。
专有名词保留，产品名、软件名、技术术语、品牌名、代码标识符、英文缩写（如 Cursor、API、GPT-4）保留原文，自然嵌入译文。
```

## 响应速度与异常输出排查

- 首次请求或模型已被空闲卸载后，请求需要重新加载模型，耗时可能明显增加。
- 本插件使用 `stream: false`，Bob 会在模型生成完毕后收到完整译文，因此不会逐字显示生成过程。
- 偶尔出现与原文无关的额外词语（例如译文开头多出一个词），可能是模型生成异常。插件不应直接删除固定词语，因为该词在其他语境下可能是正确译文。
- 建议用同一条原文和相同参数分别直连本地 `/v1/chat/completions` 与通过 Bob 翻译。如果两边都出现异常，优先排查模型、量化版本和采样参数；如果仅 Bob 出现，则对比 Bob 实际发送的请求内容。

## 参数建议

Hy-MT2 官方推荐参数因模型规格不同而异。当前插件默认值为 `temperature=0.7, top_p=0.6, top_k=20, repetition_penalty=1.05, max_tokens=4096`，适用于对应的 1.8B / 7B 配置；其他规格请参考模型官方文档调整。对短文本可测试降低 `max_tokens`，但它是输出上限，不会单独导致模型一定生成更多内容。

官方模型说明：https://github.com/Tencent-Hunyuan/Hy-MT2


## 流式输出

- 「流式输出」默认开启。Bob 1.8.0+ 支持 `$http.streamRequest()` 和 `query.onStream`；更旧版本或没有流式回调时自动使用非流式请求。
- 管理器会在 MLX 后端返回 `text/event-stream` 时逐块转发，普通 JSON 请求仍按原方式处理。
- 如果流式请求没有产生可用译文或返回错误，插件会额外发起一次非流式请求。若已正常收到译文片段，则不重复请求。
- 流式输出主要改善首字显示时间；模型冷启动仍然需要等待，不能消除模型加载时间。
